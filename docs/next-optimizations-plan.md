# QYReader 后续优化计划

更新日期：2026-10-15。依据本仓库当前源码调查编写，以下为待实施方案；文中的新接口名称是建议契约，并不代表已有功能。

## 交付边界与执行顺序

- 当前会话交付 **v2.2.0 划线笔记优化**：保留现有主题、字形和控件风格，改成选区附近的小浮条，完善划线、写笔记与已有标记操作。
- 本文所列功能在本项目的**新会话**执行，从第 1 阶段睡眠定时开始，按阶段完成实现和验收，再推进下一阶段。
- 本文不把后续功能列为 v2.2.0 已实现内容。后续会话不自动改版本号、打标签、推送或发布新版本；另有明确发布指令时再执行。
- 所有阶段沿用唯一 `SpeechController → PlaybackService → DesktopBridge` 状态链，主窗和悬浮窗消费同一播放状态。预生成可以有任务队列，但不创建第二个播放控制器或独立播放进度。
- 继续采用免费、无需 API Key 的现有 Edge、Kokoro、Windows SAPI。模型留在安装包外；视觉沿用当前界面，不重做全局主题。
- 新会话先检查当前 Git 状态与实际文件。既有未提交内容全部保留，按文件核对变更归属；禁止通过 reset、clean、restore 或整目录覆盖恢复工作区。

| 顺序 | 阶段 | 完成条件 | 后续依赖 |
| --- | --- | --- | --- |
| 1 | 睡眠定时 | 主窗和悬浮窗共享倒计时及章末停止，三引擎停止边界可验证 | 可独立完成 |
| 2 | Edge 章节预生成与缓存管理 | 可选择章节、查看进度、暂停继续、验证及清理，播放优先 | 为第 3 阶段提供任务和管理界面 |
| 3 | Kokoro 章节预生成与持久保留 | 本地生成接入同一管理界面，保留章节不被临时缓存淘汰 | 依赖第 2 阶段通用契约 |
| 4 | 音色中心 | 三引擎统一试听、收藏、搜索，状态与可用性明确 | 复用现有试听播放链 |
| 5 | 一键备份恢复 | 可校验的完整快照、恢复预览、失败回滚及路径重定位 | 纳入前几阶段新增设置与清单 |
| 6 | 书架批量管理 | 多选、批量分类/标签/已读状态，单次原子保存 | 复用现有分类与书架数据 |

## 当前源码事实与缺口

| 领域 | 已有实现 | 实际缺口 / 注意点 |
| --- | --- | --- |
| 播放状态 | `novelreader/playback_service.py` 包装唯一控制器；`floating_reader_service.py` 复用它；Qt 定时消费播放事件 | 没有睡眠定时契约；底层 `_run_session()` 会自动跨章，仅在前端收到跨章事件后停止可能来不及 |
| Edge 缓存 | `tts_engine.py` 的 `WholeBookCacher`、`start_book_cache()`、暂停/继续/取消、进度、完整性检查、容量索引 | 当前生产 Bridge 没有完整缓存管理入口；旧启动函数会给控制器的 `_book_id` 赋值；管理另一书缓存时不能改变当前播放书籍 |
| Edge 调度 | `_EdgeRequestGovernor` 已按 playback、recovery、prefetch、cache 分优先级；缓存使用单工作线程和全局退避 | UI 需要把限流暂停、失败、磁盘不足转为可理解的状态；旧进度主要依赖任务总数，不能直接当作内容一致性证明 |
| Kokoro | `kokoro_service.py` 已有模型切换、单生产者优先队列、同内容请求合并、逐句 WAV 缓存；缓存键包含模型包散列、音色、语速和文本 | 当前 500 MiB 自动淘汰缓存，没有书/章节持久保留清单；近期 Future 保护不能替代“离线章节保留” |
| 音色中心 | 设置页已有三引擎分组；`PlaybackService.preview()` 可保存、恢复书籍位置；统计用 `purpose` 区分试听 | `qt_bridge.py` 的 `previewVoice` 当前只接受已就绪 Kokoro 音色；没有统一收藏与搜索 |
| 数据 | `library.json` 存书架、进度、书签笔记、设置和分类；`reading_stats.sqlite3` 存统计；正文缓存与源文件备份由 `storage.py` 管理 | `backup_library()` 是首次功能写入前的单文件备份，不能代替整套备份恢复；自定义缓存与外部模型目录需要显式盘点 |
| 书架 | `feature_store.py::OrganizationService` 支持单书分类、标签和阅读状态；`App.jsx` 有筛选和卡片菜单 | 现有 `organizationUpdate` 只接收一个 `bookId`；缺少多选模式和原子批量更新 |

## 第 1 阶段：睡眠定时

### 用户操作与首版规则

- 在现有播放控制区域增加小型定时入口，提供 **15 / 30 / 60 分钟、自定义分钟、读完本章、取消定时**；复用当前弹层样式。
- 主窗显示“剩余 29:58”或“本章结束停止”，悬浮窗在控制栏可见时展示同一状态，避免挤占当前句。
- 倒计时按实际经过时间计算，暂停朗读不暂停倒计时；到期停止声音、保留当前位置，用户再次点播放才继续。更换倒计时会替换原任务，不叠加。
- 自定义首版建议限制为 1–720 的整数分钟，前后端同时校验；界面清楚写“分钟”。
- “读完本章”绑定设置时的书籍和章节，在该章最后一个实际朗读片段完成后停止，不播放下一章第一句。空白章、末章、从章中位置开始也遵循这一规则。
- 切换书籍或手动跳出目标章节时取消章末定时并说明原因，避免把旧章节条件带到新位置；同章跳转保留。普通倒计时可跨同一应用内的书籍切换继续。
- 手动停止和退出应用取消定时；暂停保留。重新启动应用默认无活动定时。取消定时只撤销计划，不改变当前播放。
- 系统恢复后先检查是否已到期，再允许声音继续；到期时若正在试听，先结束试听并恢复书籍上下文，再执行停止，不能自动恢复书籍朗读。

### 服务、Bridge 与数据

1. 把定时状态放在宿主播放协调层，使用可注入时钟；Qt 定时器负责触发检查，前端仅显示。不能依赖浏览器后台 `setTimeout` 或两个窗口各自递减。
2. 计划新增 `SleepTimerState`：模式、剩余毫秒、目标书籍/章节、结束原因和版本序号。新增设置/取消/查询请求，并随共享状态事件发给两个窗口；保留 `schemaVersion: 2`，以兼容的新增字段/动作扩展。
3. `SpeechController._run_session()` 在跨章前增加受当前会话/代次约束的停止条件；`PlaybackService` 接收明确结束原因并同步位置。不能仅在 Qt 收到 `chapter` 事件后调用停止。
4. 同步更新 `qt_bridge.py`、`prototype/src/bridge.d.ts`、`bridge.js` 的 Qt 与 demo 传输。活动定时放在内存；如保存常用时长，只追加设置键，旧书架自动采用默认值。

### 验收

- 注入时钟覆盖 15/30/60、自定义边界、覆盖设置、取消、暂停、到期、休眠恢复、切书、跳章、重启和试听冲突。
- SAPI、Edge、Kokoro 在普通播放、缓冲、暂停状态下都能到期停止；过期合成回调不能重新发声。
- 章末判断覆盖末章、空章、Markdown 原文与朗读文本偏移、句末暂停/恢复，以及跨章预取已经完成的情况。
- 浏览器验证双窗口显示和键盘操作；真实 Qt 主窗/悬浮窗互相设置、取消、关闭主窗到托盘后仍按时停止。
- 使用短时测试时钟做自动化，真实桌面再做一次短倒计时与一次章末扬声器验证。未听到实际声音时只报告状态验证通过。

## 第 2 阶段：Edge 章节预生成与缓存管理

### 范围与界面

- 在当前书籍菜单/章节目录增加“准备离线听书”；首版提供当前章、后续若干章、自选章节。整本任务通过明确选择进入，不自动为所有书籍下载。
- 管理页按书籍与音色/语速展示章节完成度、已完成/总片段、实际占用、排队/准备中/暂停/失败/完成；支持暂停、继续、取消任务、检查并补齐、清理选中缓存。
- “取消任务”保留已生成片段；“清理缓存”单独显示删除范围和大小并确认。正在播放的文件需要跳过或延迟删除。
- 沿用现有节流和退避，提示如“服务繁忙，已暂停，可稍后继续”。首版不接入旧缓存器的完成后自动关机功能。

### 服务、Bridge 与数据

1. 建立薄的缓存任务服务，调用现有缓存器和统一请求治理器，不另写 Edge 合成通道。显式传入书籍、章节、音色、语速；消除旧 `start_book_cache()` 对当前播放 `_book_id` 的副作用。
2. 后台建立章节任务清单；Qt 请求立即返回 `jobId`，后续发进度事件。不能在 GUI 线程调用可能等待 60 秒的旧进度扫描。
3. 新清单记录书籍内容指纹、章节范围、切句版本、引擎、音色、语速和缓存格式版本。相同任务幂等继续，内容或参数变化时不得复用错误音频。
4. 新增通用缓存查询/创建/暂停/继续/取消/验证/清理契约，结果带 `jobId`、任务状态、章节统计、占用和结构化错误。Qt、demo 和类型定义保持一致，为 Kokoro 预留 `backend` 字段。
5. 兼容现有 `<tts_cache>/<book_id>/<voice>/<rate>` 路径与进度文件，先验证再纳入管理。旧数据缺少内容指纹时显示待校验，不直接宣称已离线就绪，不无条件重写或清空旧目录。

### 验收

- 用模拟合成验证范围选择、暂停继续、重启恢复、失败不虚增完成度、缺片补齐、不同内容/语速隔离。
- 缓存 B 书期间播放 A 书，音色、当前位置、进度与书籍 ID 均正确；反复点击只产生一个同配置任务。
- 通过请求调度测试证明播放优先与退避；联网只做少量必要验证，不用整书任务压测服务。
- 在完整准备的测试章节上禁用测试合成入口，证明播放可全部命中缓存，再做离线桌面听音；不修改机器的持久网络设置。
- 清理只作用于用户选定的已解析缓存路径；原文、笔记、统计、未选中书籍和播放中的音频保持可用。

## 第 3 阶段：Kokoro 章节预生成与持久保留

### 范围与服务

- 复用第 2 阶段的任务与管理界面，增加 Kokoro 引擎选择。显示“首次需要准备，完成后可离线听”，不给出未实测的即时完成承诺。
- 通过现有 `KokoroService.request(..., priority=...)` 调度，后台章节任务低于当前播放、跳转和试听；小批入队，限制待生成数，不一次提交整书。
- 每个任务固定模型包、INT8/FP32、音色、语速和内容指纹；模型切换时暂停不兼容任务，旧模型完成回调不能污染新任务。
- 区分“临时缓存”和“保留的离线章节”。增加持久清单和文件引用关系；保留片段、正在播放片段及有效任务依赖不得被临时缓存淘汰。
- 临时缓存继续受容量约束；持久保留由用户显式释放，开始前检查剩余空间，磁盘不足时暂停并展示已完成内容。不能自动删除保留章节腾空间。
- 共享文本生成一次可被多个章节引用；删除某一章节只移除其引用，仍被其他保留章节使用的文件继续保留。

### 兼容与验收

- 原 500 MiB 逐句缓存先作为临时缓存读取，新增索引采用独立版本文件，不重命名既有音色 ID，也不重新下载已安装模型。
- 验证任务取消、程序重启、磁盘不足、模型切换、同文本合并、缓存淘汰以及多章节共享引用。
- 两引擎任务使用统一页面，缺模型时提供既有下载/导入入口；SAPI 明确显示不支持预生成，仍可实时朗读。
- 用混合长短句和同机背景负载测冷生成及缓存回放，记录首句等待、总耗时、音频时长、RTF、句间等待、峰值内存与磁盘占用。后台生成期间必须仍可及时播放、暂停和跳转。

## 第 4 阶段：统一音色中心

### 范围与实现

- 复用设置中心布局，保留三引擎分组；增加搜索、收藏、中文名称、在线/离线状态及不可用原因。收藏仅保存稳定音色 ID；系统音色暂不可用时保留收藏并标记。
- 三引擎使用相同的短中文试听文案；试听可以取消，点击另一音色替换当前试听。试听与正式朗读音色选择分别表达，避免试听悄悄保存音色。
- 扩展现有 `previewVoice` 校验至实际已枚举的 Edge/SAPI/Kokoro 音色；继续走唯一 `PlaybackService.preview()`，补齐试听结束、取消、异常时的上下文恢复。
- 试听不累计听书时长、不更改正文进度；原来正在播放的书籍试听后保持暂停，用户明确点继续才恢复。配合第 1 阶段明确处理定时到期。
- 收藏追加存入 `library.json` 设置，搜索在 UI 内完成；统一试听状态通过 Bridge 发给两种窗口，保留现有音色 ID 和默认值。

### 验收

- 搜索匹配中文名/引擎/音色 ID；收藏重启后存在；缺模型、离线 Edge、消失的系统音色显示正确原因。
- 重复试听、跨引擎快速切换、取消、异常和同时设置睡眠定时后，恢复原书籍、章节、字符位置和音色，统计不增加试听时间。
- 三类音色实际扬声器试听单独记录。自动化只证明状态和调用正确，不证明音质或无爆音。

## 第 5 阶段：一键备份与恢复

### 范围与数据

- 设置中心提供备份与恢复。默认备份书架、可读取正文/源文件副本、进度、笔记、分类标签、排序、统计和可迁移设置；音频缓存与模型为可选的大体积内容，先显示预计大小。
- 采用版本化清单，逐文件保存相对路径、大小和校验值，记录缺失源文件/正文，不把缺失内容标成完整成功。
- 盘点 `library.json`、正文缓存及 `sources`、`reading_stats.sqlite3`，再纳入新增离线章节清单与收藏设置；SQLite 使用一致性备份方式，不能直接复制正在写入的数据库文件当作完整快照。
- 尊重 `paths.py::default_data_dir()`：源码、安装版、`DOUBAO_NOVEL_DATA` 测试目录各自解析；额外盘点自定义缓存和模型目录，只打包明确纳入的文件。

### 恢复流程与兼容

1. 读取清单、校验版本和文件散列，在临时区域完整展开并验证安全相对路径、文件类型与大小；禁止绝对路径、目录穿越或链接逃逸。
2. 展示书籍数、笔记数、统计时间范围、缺失内容、将被替换的数据和目标位置。首版采用完整快照恢复，不隐式合并两个书架或统计库。
3. 用户确认恢复后，先为当前状态生成可恢复快照，暂停播放与写入并保存待写进度；在成功校验的暂存区准备数据，再执行可回滚替换。取消、空间不足、校验失败或中途异常均保留原数据。
4. 保留书籍 ID 和笔记锚点，重定位包内正文、源备份、模型和音频路径；不沿用另一台电脑不存在的绝对路径，不以新路径重算 ID 导致进度或笔记失联。
5. 原始外部源文件保持原样；无法恢复模型时保留可重新选择/导入的状态。日志、下载临时文件和运行中锁文件不作为用户备份内容。

### 验收

- 全部先在隔离 `DOUBAO_NOVEL_DATA` 目录测试；生成带正文、跨章节笔记、分类、统计与缓存引用的测试数据，备份后恢复到另一目录并逐项对比。
- 覆盖旧版本数据缺省值、未知字段保留、损坏包、错误散列、恶意路径、磁盘不足、取消及中途失败回滚。
- 打开恢复后的书籍，核对正文、划线、阅读/朗读位置、统计和缓存命中；切勿对用户真实数据做破坏性恢复测试。

## 第 6 阶段：书架批量管理

### 范围与实现

- 内容库增加明确的多选模式与已选数量；支持当前筛选结果全选、取消选择，以及批量设置/清除分类、添加/移除标签、标记已读/阅读中/未读。
- 批量添加标签采用并集、移除采用差集，保留其他标签；首版不把“替换全部标签”混入同一按钮，也不连带删除书籍或源文件。
- 已读状态继续复用 `reading_status_mode`：人工设置后进入 manual，自动进度更新不覆盖；显式恢复自动才按原规则推导状态。
- 扩展 `OrganizationService` 批量动作和 Bridge 类型，一次校验全部 ID 与 patch，在同一 `library_write_lock` 内读取最新文件、修改指定字段、原子保存；任一目标失效则整批不写并给出提示。
- UI 保留已选 ID，不依赖卡片 DOM 是否仍挂载；切换筛选后清楚显示选中范围，执行前展示数量。沿用当前卡片和弹层样式。

### 验收

- 多分类、多标签、混合阅读状态，筛选/排序/虚拟列表切换后选择准确；执行一次只写一次文件。
