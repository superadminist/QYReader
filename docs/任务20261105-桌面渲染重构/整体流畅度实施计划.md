# 阅读器整体流畅度实施计划

目标是在保留现有布局、主题、字体、圆角、动画和全部阅读功能的前提下，让窗口操作、书库和正文滚动、打开正文、设置切换和浮窗往返都更连贯。以现有 Qt 阅读器作为交付入口。换宿主和拆进程是技术候选，采用与否由同条件的实际性能和功能回归结果决定。

| 场景 | 怎么验收 |
| --- | --- |
| 书库悬停、设置切换、浮窗短动画 | 同机同刷新率的帧间隔 P95 不超过 1.25 个刷新周期，60 Hz 约 21 ms。并检查长任务和肉眼可见的跳帧。 |
| 书库和目录连续滚动 | 下滚、上滚、反向分开统计，P95 不超过 2 个刷新周期，60 Hz 约 33.4 ms，稳态超过 50 ms 的间隔低于 1%。 |
| 正文加载和滚动 | 分开记录打开到正文可读、正文滚动的帧间隔。正文滚动至少不退步，并检查大章节、跳目录和连续翻页。 |
| 书卡菜单 | 记录首次、同点和交替位置打开。输入到可见并进入下一帧的 P95 不超过 100 ms，同时检查菜单样式、定位、关闭和操作。 |
| 主窗和浮窗 | 在正式桌面检查启动、往返、拖缩、最大化恢复、跨屏以及朗读时操作。关注闪白、闪黑、透明丢失、状态与文字错位。 |

正式性能对比使用同一台机器、刷新率、窗口大小、DPR、主题和 300 本合成书库，首本 1000 章。记录软件版本、实际渲染后端和场景原始样本，基线和候选交替执行。浏览器预览用于快速验证交互、定位 React 和页面布局开销。正式 Qt 的桌面呈现、窗口操作和朗读体验需要分别实测。任何单场景收益都不能作为整体验收结果。

实施顺序如下：

1. 先把已定位的书卡菜单重复更新从书库列表中移出。历史实验显示，菜单节点反复进出会触发额外布局，但收益大小须在当前前端重测。
2. 在现有 Qt 入口采集剩余场景的基线。优先处理实测中影响范围最大的渲染、布局或输入阻塞，拆开验证透明合成与硬件渲染，避免把两项配置的收益归给其中一项。
3. 每项改动先保住原外观、交互和业务行为，再比较修改前后数据。最终按整张表验收，并保留可回退的现有运行方式。

历史 Quick 隐藏验收停在启动阶段，尚无可用的整机流畅度对照。该试验的故障和证据继续保留，当前性能工作可在现有阅读器独立进行。

## 设置首开与标签切换：拆分布局、绘制和宿主开销（2026-11-12）

## 音量改为播放起点应用：静音期改音量的 184ms 枚举归零（2026-11-16 20:15–20:30）

## edge_tts 按需导入：热启动 −0.225 秒，首次 Edge 朗读 +0.244 秒（2026-11-17 09:30–09:50）

第 8 节第 3 条的甲。产品改动 1 个文件 2 处，回归 +3 例。

### 改法

`novelreader/tts_engine.py` 顶层原来是 `try: import edge_tts / except: edge_tts = None`，`edge_tts` 全文件只被 `synth_audio` 用到。改为：

```python
_EDGE_TTS_UNLOADED = object()
edge_tts = _EDGE_TTS_UNLOADED

def _edge_tts_module():
    global edge_tts
    if edge_tts is not _EDGE_TTS_UNLOADED:
        return edge_tts
    try:
        import edge_tts as module
    except Exception:
        module = None
    edge_tts = module
    return module
```

`synth_audio` 取 `module = _edge_tts_module()`，`module is None` 时仍抛原来的 `RuntimeError("edge-tts 未安装")`。

**为什么用哨兵而不是 `None`**：`edge_tts = None` 在现有代码与 `test_edge_resilience.setUp` 里是"未安装"的硬信号（那条 setUp 专门防止忘记打桩的用例真的联网）。若用 `None` 表示"还没加载"，加载器会把测试桩覆盖回真模块，SAPI 回退也会被误触发。

失败路径不变：第一次合成抛 `RuntimeError` → `_synth_audio_governed` 包成 `EdgeSynthesisError` → 既有的"一次性 SAPI 回退"。只是从"启动时知道"变成"第一次合成时知道"。

### 启动路径核对

`import novelreader.qt_host` 之后、`SpeechController()` 之后、`set_voice("zh-CN-XiaoxiaoNeural")` 之后、`list_edge_voices()`（9 个静态音色）之后、`shutdown()` 之后，`edge_tts` 都不在 `sys.modules`。第一次导入落在 `synth_audio`，且在 `asyncio.wait_for` 之外，不吃 30 秒合成预算。

### 取舍与未验证

### 为什么另起脚本而不是给 `run.py` 加分支

`run.py` 的每条判据都要求窗口**不可见**：`create_desktop` 建私有桌面、`qt_host.py` 在 `show()` 前无条件设 `WA_DontShowOnScreen`、任何自有可见窗判 `owned-window-ws-visible` 并停批、`foreground_failed()` 要求前台不属于本 Job。在这些前提上开一条反向分支，等于把已经验证过的审计路径当赌注。改为新增 `desktop-lab/visible_accept.py`，复用同一套 `QY_LAB_*` 环境变量、`owner.json`、`command.json` 契约，只换启动桌面与判据方向。

### 开关与工具

`desktop-lab/qt_host.py` 新增两个默认关闭的环境开关：`QY_LAB_VISIBLE=1` 去掉 `WA_DontShowOnScreen`/`WA_ShowWithoutActivating`/`WindowTransparentForInput` 与浮动窗的隐藏包装；`QY_LAB_AUDIO=1` 同时放开产品原生朗读路径（不设则静音且拒绝播放）。`metadata()` 里的 `hiddenOnly`/`muted`/`voicePrewarmDisabled` 改为真实值，并补 `visible`/`hWnd`/`exposed`/`dontShowOnScreen`/`transparentForInput`——判"到底上没上屏"用 `windowHandle().isExposed()`，不靠猜。

`visible_accept.py` 三种用法：`--desktop active`（自动跑 12 个用例，约 100 秒）、`--hold`（窗口留着，人做拖缩/跨屏/浮窗往返，按回车结束）、`--audio`（放开真实朗读）。`--desktop private` 走私有桌面，只用来验管线，用户看不到。

`benchmark.mjs` 三处改动，全部只在 `owner.visibleRun` 存在时生效：限制说明换成可见口径、校准用例改名 `renderer-calibration`、不覆盖可见运行的排除理由。隐藏批次的报告字段不变。

### 三件决定下一趟怎么跑的事实

1. Qt 合成是产品自己选的软件路径：`novelreader/qt_rendering.py` 在 Windows 默认 `QT_QUICK_BACKEND=software`，只有 `QYREADER_RENDER_MODE=hardware` 才走硬件，注释写明加速 Quick 合成会整帧丢失。`graphicsApis=Software` 是现状。
2. 私有桌面下 Chromium 拿不到 GPU：宿主 stderr 有 `Failed to create GLES3 context, fallback to GLES2` 与 `Failed to create shared context for virtualization`。私有批次因此只作管线证据。
3. 本机是 `AMD Radeon(TM) Graphics`（驱动 31.0.14051.1000）+ `console` 会话（ID 1，运行中），不是远程桌面。上屏跑有机会拿到硬件光栅。
