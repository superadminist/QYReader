## 用户要求与执行边界

- 保留当前布局、主题、字体、图标、圆角、动画意图和操作流程。性能优化不得通过删除动画、减少功能或换成其他阅读器的 UI 达标。
- 主窗口与浮窗共享一个播放控制器、播放位置和朗读状态；保留 Edge、Windows SAPI、Kokoro 及现有缓存和预取规则。
- 浮窗必须保留背景独立透明度、清晰文字、自由移动与缩放、当前句优先、悬停显示控制、主窗往返及独立窗口行为。
- 后台操作不得置顶应用、抢焦点、移动系统鼠标、发送系统键盘输入或自动播放声音。不自动启动任何可见窗口；隐藏测试进程不显示到桌面，不修改系统显示、缩放或 GPU 配置。
- 可在新会话推进隔离原型、适配层实现和后台测试。实际屏幕与听音验收等用户明确安排后再做；未安排时登记待验项目，继续完成独立工作。
- 保留所有已有修改和未跟踪文件；不使用 reset、clean、restore 或整目录覆盖处理工作区。不自动提交、推送、打标签、升级产品版本、制作正式发布或覆盖安装现有软件。
- 本任务不包含新业务功能、全局视觉重设计、数据库重建、数据格式迁移或批量改写历史文件。

## 候选技术栈与选型条件

| 路线 | 验证目的 | 必须解决的条件 |
| --- | --- | --- |
| Electron 加现有 React 加独立 Python 服务 | 验证成熟桌面壳和 Chromium 渲染路径能否改善体验 | 透明浮窗自由缩放、圆角和文字透明度分离；受控异步通信；进程生命周期和打包 |
| Tauri 2 加现有 React 加独立 Python 服务 | 验证 Windows WebView2 的窗口与渲染路径 | 浮窗、防闪白、多屏缩放、原生窗口操作、Rust 适配及 Python sidecar 生命周期 |
| 当前 Qt 的不透明硬件模式 | 作为低迁移成本的参照方案 | 历史闪白问题、浮窗仍透明、全局合成后端影响及实际桌面稳定性 |

Electron 优先看生态与运行时可控性，Tauri 优先看现有 Windows 窗口需求的适配结果。不能预先认定任一候选一定更快。Electron 官方列有透明窗口缩放限制，因此浮窗验证必须前置；Tauri 的 Windows 透明窗口也需要检查创建时的白闪。

pywebview 加 Edge Chromium 仅作为必要时的快速排查工具，不默认增加第三套长期维护的完整原型。Flutter、WinUI、QML 整套 UI 重写不属于首轮范围。若两个候选都无法满足关键功能，保留 Qt，给出失败证据与后续方案，不通过删减功能宣布选型通过。

## 目标架构

现有 React 组件通过统一桌面接口调用宿主适配层；Qt、Electron、Tauri 的差异集中到传输与窗口适配中。Python 业务进程负责书库、阅读、数据、语音和共享播放状态。主窗口与浮窗订阅同一服务的事件，不各自创建一套业务实例。

- 保留现有 `schemaVersion: 2` 契约语义，优先兼容扩展。请求与事件带有明确 ID、版本或会话信息，支持超时、取消、过期响应丢弃及订阅清理。
- 首轮可采用带请求 ID 的异步 JSON 消息，经独立进程标准输入输出传输；日志单独走标准错误。大正文使用现有窗口化接口，不持续传输整本内容。确需其他传输时记录原因并保持仅本机访问。
- 文件对话框、托盘、快捷键、窗口拖动缩放、外部链接、安装更新等由宿主提供；业务服务不直接依赖窗口对象。
- 不在 Electron 主进程、Tauri 窗口线程或 React 渲染线程执行导入解析、同步磁盘扫描、语音合成和长时间等待。事件按需合并，保持当前句与关键播放事件的顺序。
- `connectBridge` 必须能识别新宿主并验证协议。生产模式缺少宿主连接时显示错误，不能静默显示 demo 书库或假成功。
- 各壳实验使用独立数据目录和打包产物。访问真实书库进行兼容验证前建立可检查备份，首轮仅使用隔离副本；不直接迁移或改写用户数据。

## 性能测量与目标

以下是本任务的初始工程目标，不是已有结果。以相同机器、相同生产构建、相同逻辑视口、相同 DPR、相同数据与刷新率比较；60 Hz 下一个刷新周期约 16.7 ms。其他刷新率按实际周期换算，不使用统一的“60 FPS”描述所有屏幕。

| 场景 | 初始目标 | 测量要求 |
| --- | --- | --- |
| 稳态悬停、设置切换与浮窗短动画 | rAF 帧间隔 P95 不高于 1.25 个刷新周期，60 Hz 约 21 ms | 同时检查 trace 中的布局、绘制与长任务 |
| 书库与目录连续滚动 | P95 不高于 2 个刷新周期，60 Hz 约 33.4 ms；稳定区间超过 50 ms 的间隔占比低于 1% | 向下、向上、反向分别报告，不合并成单一好看的数值 |
| 菜单操作 | 输入到菜单状态就绪并到下一 rAF 的 P95 不高于 100 ms | 与“整段操作中的帧间隔 P95”分列，避免混用 |
| 实际可见动画与窗口变化 | 无可复现的内容丢失或黑白闪帧，操作连续 | 用真实桌面录制或呈现证据检查，隐藏截图不能替代 |
| 资源与稳定性 | 记录启动、空闲、滚动、双窗和长时运行的内存、CPU/GPU、退出残留 | 不预设 Tauri 一定更省内存，不以更大开销掩盖持续增长 |

- 使用 300 本书与 1000 章隔离数据作为可比基线，再增加大书库与长正文边界场景。所有壳使用一致内容，不接入真实用户数据做压力测试。
- 每个候选至少运行 3 个独立进程轮次，先预热，再交错或反向执行候选，报告每轮和分布；后台其他工作造成噪声时标注，不发布精确收益百分比。
- 每轮开始和结束都读取页面 DPR、宿主 DPR、视口及实际图形后端，记录所有屏幕缩放；仅设置环境变量不足以证明条件一致。
- 记录提交、前端 JS/CSS 散列、宿主和浏览器版本、Python 版本、显卡/驱动与后端信息。D3D11 API 名称不能单独证明使用了物理 GPU 而非软件适配器。
- 性能采样与图像抓取分开运行，避免抓图本身改变帧时间。rAF 反映渲染调度；输入到下一 rAF 也不等同于实际显示延迟。
- 保存原始结果、失败与异常日志。无效 DPI、旧进程或错误页面的运行不得计入有效对照；修正后用全新目录重跑。

完整功能清单以 P0 当前源码盘点为准；表中条目不是新增业务需求。受联网、模型或实际扬声器条件限制的场景分别标记“模拟通过”“状态通过”“真实验证通过”或“待验”。

主窗优先评估不透明宿主、主题一致的初始底色和系统圆角。系统圆角与现有 22 px 视觉可能不同，必须对照，不能以改成方角通过功能验收。浮窗单独验证透明与 30 px 圆角，不能全窗统一设置 opacity 导致文字一起透明。

## 隔离方式与回退

- P0 根据当前工作区选择不污染原入口的实验目录或入口，保持依赖边界清楚。若使用额外 worktree，先确认它能包含本次需要的实际代码；不能因未提交内容未被复制而测试到另一个版本。
- 每次测试使用唯一运行 ID、新输出目录、独立缓存与数据副本。控制命令和元数据必须匹配本次运行，启动失败立即失败，不继续连接旧 CDP 端口。
- 进程与端口只监听本机。关闭测试时按可验证的命令行/运行 ID 清理本任务拥有的进程，不结束用户正在使用的阅读器或浏览器。
- 旧 Qt 启动入口与数据格式保持可回退。新壳异常退出、服务断连或协议不符时显示可理解错误，不吞错或误报保存成功。
- 背景测试不得打开 DevTools 可见窗口、置顶测试窗口、自动播放提示音，或改变用户系统偏好。可见验收记录由用户安排，不以“测试需要”为由自行抢焦点。
