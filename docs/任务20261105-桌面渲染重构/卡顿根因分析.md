# 书库卡顿 / 书封悬停动画卡顿 —— 根因分析

## 1. 一句话结论

**（现状事实）** 卡顿不是前端动画或业务代码造成的，而是 QtWebEngine 透明窗口 + AMD 核显环境下，进程被 `QT_QUICK_BACKEND=software` 强制走「软件合成」，连带让 Chromium 禁用 GPU（`gl=disabled, angle=none`）。滚动、悬停动画的合成与栅格工作全部落到 CPU 主线程，帧时间从硬件合成的 16.7ms 恶化到 83.4ms。

---

## 2. 现象

**（已确认需求）** 用户主观反馈两点：

1. 内容库滚动不丝滑，有明显卡顿；
2. 鼠标悬停书封时，上移动画明显卡顿。

**（现状事实）** 实测数据（真实宿主上屏验收，`visible-accept-active-20261117-102928-71f8f468`）：

| 场景 | 透明 + 软件合成（验收现状） | 透明 + 硬件合成（transparent-hardware 实验） |
|---|---|---|
| `book-hover`（书封悬停） | **83.4ms**（判据 ≤21，超 4 倍） | **16.7ms** |
| `settings-open-tabs-close` | 50.0ms（超判据） | 达标 |
| 其余 10 项用例 | 通过 | 12 项全部达标 |

---

## 3. 根因定位过程（关键实验）

排查经历了多次假设修正，最终锁定根因。按时间顺序，每步标注结论分类：

### 3.1 最初的错误假设：以为「透明窗口」是根因

- **（现状事实，已修正）** 现象：透明窗口（`WA_TranslucentBackground`）下滚动与悬停都卡。
- **（现状事实）** 验证方式：做「不透明 + 软件合成」对照（`opaque-default`）。
- **（现状事实）** 结果：GPU 依然被禁用。说明透明窗口本身不是根因，只是表象。

### 3.2 修正：真正的开关是 `QT_QUICK_BACKEND=software`

- **（现状事实）** 关键发现：`QT_QUICK_BACKEND=software` 会连带让 Chromium 禁用 GPU（`gl=disabled, angle=none`）。
- 即：为「圆角透明」引入的软件合成环境变量，顺手把整个 Chromium 渲染管线按回了 CPU。

### 3.3 决定性实验：三个渲染模式的帧时间对照

| 模式 | 环境 | `book-hover` 帧时间 | 结论 |
|---|---|---|---|
| 透明 + 软件合成（现状） | `QT_QUICK_BACKEND=software` + `--disable-gpu` | **83.4ms** | 卡 |
| 透明 + 强制 GPU | `--use-angle=d3d11` | **333ms** | 更卡（`canSupportThreadedTextureMailbox=False`） |
| **透明 + 硬件合成** | transparent-hardware | **16.7ms** | **丝滑，12 用例全达标，圆角保留** |

**（现状事实）** 强制 GPU（`--use-angle=d3d11`）行不通——AMD 核显上 `canSupportThreadedTextureMailbox=False`，反而更慢。

**（现状事实）** 真正有效的是「透明 + 硬件合成」（transparent-hardware），它同时满足两个目标：

1. 圆角透明 UI 保留（透明窗口特性不变）；
2. 丝滑（渲染走硬件合成，帧时间回到 16.7ms）。

---

## 4. 根因总结

```
（现状事实）用户要「圆角透明」UI
        │
        ▼
引入 QT_QUICK_BACKEND=software（软件合成）
        │
        ▼
连带 Chromium 禁用 GPU（gl=disabled, angle=none）
        │
        ▼
滚动/悬停动画的合成与栅格工作全部压到 CPU 主线程
        │
        ▼
帧时间 16.7ms → 83.4ms，主观卡顿
```

**（现状事实）** 根因一句话：`QT_QUICK_BACKEND=software` 这个为「透明圆角」服务的开关，副作用是禁用 Chromium GPU，这才是卡顿的真正来源。透明窗口本身不是根因。

---

## 5. 解决方案：渲染模式开关

**（已确认需求）** 由于「透明圆角」与「丝滑」在 transparent-hardware 下可以兼得，采用**加开关**方案：

- 默认「流畅优先」= 硬件加速（transparent-hardware）：圆角 + 丝滑都保留，是推荐态。
- 可选「稳定优先」= 软件合成（software）：作为回退态，供特殊显卡/驱动异常时切换。

### 5.1 两个模式的行为

| 渲染模式 | 环境变量 | Chromium GPU | 圆角透明 | 帧时间 |
|---|---|---|---|---|
| `hardware`（默认） | 不设 `QT_QUICK_BACKEND=software` | 启用（硬件合成） | 保留 | 16.7ms 丝滑（实验） |
| `software` | `QT_QUICK_BACKEND=software` + `--disable-gpu` | 禁用 | 保留 | 83.4ms 卡顿（现状） |

### 5.2 关键实现约束

**（现状事实）**

1. `configure_rendering()` 必须在 `QApplication` 创建之前调用，否则环境变量不生效。
2. 渲染模式持久化在 `library.json` 的 `settings.render_mode` 字段。
3. 入口逻辑在调 `configure_rendering()` 之前读取该字段，决定是否设置 `QT_QUICK_BACKEND=software`。
